Technical Autopsy: The 5 Critical Errors in Original Notebook

1. Data Leakage & Test Distribution Corruption via scaler.fit_transform(X_test)

In cell 34, you executed: x_train_scaled = scaler.fit_transform(X_train) followed by x_test_scaled = scaler.fit_transform(X_test).

Why this is wrong: fit_transform on the test set recalculates the mean (μ) and standard deviation (σ) exclusively on the test set instead of applying the learned training distribution. Furthermore, when you did joblib.dump(scaler, 'scaler.pkl'), you saved the test-fitted scaler! In production, single patient requests would be transformed using test sample statistics.

The Fix Applied:

Use scaler.transform(X_test) for evaluation. In the full-stack architecture, we encapsulate the scaler inside a scikit-learn ColumnTransformer and unified Pipeline so data leakage is mathematically impossible.

2. Feature Truncation Bug: df_encoded = df_encoded.astype(int)

In cell 26, you converted the entire dataframe to integer: df_encoded = df_encoded.astype(int).

Why this is wrong: The feature Oldpeak (exercise ST segment depression) is a continuous float (e.g. 1.5 mm, 2.4 mm, -0.5 mm). Converting to int violently truncated values (1.5 became 1, 2.8 became 2). In clinical cardiology, fractional millivolt depressions carry distinct prognostic significance. Truncation destroyed granular predictive signals.

The Fix Applied:

Preserve Oldpeak as float64 and handle boolean dummy columns properly without cast-truncation.

3. Imputation Data Leakage Before Train/Test Split

In cells 12-15, zero values in Cholesterol and RestingBP were imputed using the entire dataset mean prior to train_test_split.

Why this is wrong: Information from test samples leaked into the calculated training mean (244.64 mg/dl). In rigorous machine learning, missing value imputers must be fitted strictly on X_train and applied to X_test.

The Fix Applied:

Marked physiological zeros as np.nan and used SimpleImputer(strategy='median') inside the preprocessing pipeline, fitted strictly on training data.

4. Global pd.get_dummies() and Fragile Production Pickles

In cell 24, one-hot encoding was generated using pd.get_dummies(df, drop_first=True) across the entire dataset, saving loose column lists.

Why this is wrong: If a single user input in production doesn't match the exact dummy levels, or if an unseen category arrives, pd.get_dummies() creates mismatched shapes, throwing matrix dimension errors.

The Fix Applied:

Used OneHotEncoder(categories=..., drop='first', handle_unknown='ignore') inside ColumnTransformer. Now the pipeline reliably processes single JSON records or batch DataFrames with guaranteed schema consistency.

5. Single Unstratified Split (32% Test Size) Without Cross Validation

In cell 33, train_test_split(X, y, test_size=0.320, random_state=42) was executed without stratification or K-Fold CV.

Why this is wrong: A single random split can result in lucky or unlucky test distributions. Furthermore, no hyperparameter tuning was conducted for Logistic Regression, SVM, or ensemble methods.

The Fix Applied:

Implemented 5-Fold Stratified Cross Validation with comprehensive GridSearchCV, optimizing both ROC-AUC and Recall.
